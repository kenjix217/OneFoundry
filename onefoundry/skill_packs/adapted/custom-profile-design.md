# custom profile design

Use this procedure when the operator wants a new OneFoundry role or a revised role contract. Produce a proposal for review; the operator saves it in Team.

1. Define one clear responsibility, expected work orders, output, handoff recipient, and acceptance evidence. Check for overlap with an existing profile before proposing a new one.
2. Draft the profile name, instructions, memory scope (`project` or `company`), model requirement, and autonomy setting. State proposed tool IDs separately as requests; tool use requires saved and current profile permission plus Tool Gateway admission. Check the exact tool contract before recommending an ID.
3. Name input limits, protected information, outbound approval gates, and what the role must do when evidence or a tool is missing.
4. Give one normal and one failure example. Check that the profile instructions remain short enough for bound skills and work orders to fit the live text prompt limit.
5. Return the proposed fields and open operator decisions. Do not claim the role was created, connected, granted tools, or tested without OneFoundry readback.
