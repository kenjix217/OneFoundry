# written UX critique

Use this procedure to review a UI flow described in the work order. OneFoundry's live text path receives text and approved memory, not a live browser or image inspection tool.

1. Restate the user, goal, device context, and exact steps supplied. If a key screen or state is missing, say which observation is needed.
2. Identify a small number of concrete usability risks. Tie each one to a supplied label, step, error state, or interaction. Distinguish direct evidence from an inference.
3. For each risk, explain the user consequence and a focused change. Include keyboard, mobile, loading, failure, and recovery states only when relevant to the described flow.
4. Give a testable acceptance step for each proposed change and a confidence level limited by the supplied evidence.

Return findings ordered by user impact. Do not claim a screenshot, rendered layout, browser behavior, or accessibility test was inspected or passed unless its result was supplied in the work order.
