# scrollytelling scene plan

Use this procedure when a work order asks whether an interactive scroll story is justified or needs a scene outline. Inputs are the narrative claim, supplied data, audience, key transitions, publishing medium, and device constraints.

1. Decide whether a static sequence or small multiples would communicate the claim clearly. State the reason for any scroll-driven interaction.
2. Outline each scene's evidence, visible state, transition trigger, annotation, and fallback. Keep data-bound marks separate from decorative motion.
3. Describe reduced-motion, keyboard, mobile, slow-network, and static-export behavior.
4. List acceptance checks for factual continuity, first and final states, intermediate frames, and source attribution.

Return a written scene contract and open asset/data questions. This procedure does not create imagery, implement scrolling, render frames, publish a page, or verify browser behavior. Save Markdown only through admitted `write_text_artifact_v1` when requested.
