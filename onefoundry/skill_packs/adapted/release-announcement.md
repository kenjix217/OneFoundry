# release announcement draft

Use this procedure to draft communication for a release whose status and behavior are supplied as evidence in the work order or approved memory.

1. Identify the audience, channel, release identifier, actual availability, user impact, and required upgrade or migration action. If availability is unverified, call the output a proposed announcement.
2. Separate confirmed changes from planned changes. Exclude unsupported customer, security, performance, or compatibility claims.
3. Lead with what the reader can do or must change. Keep a changelog entry brief; give a longer message only when the selected channel needs it.
4. Include links or source IDs for every material claim and mark any missing release evidence for operator review.
5. Return a draft, a short fact checklist, and a publication-ready status of `ready for review` or `needs evidence`.

The output is a draft. Publishing or sending it requires the OneFoundry approval inbox and a separately admitted action. This procedure cannot publish or create cases in an external system.
