# context framing

Use this procedure before an analysis when the work order and approved memory contain scattered project facts or earlier decisions.

1. Identify the question, project, audience, and relevant time window. Keep context that changes how the question should be answered.
2. Organize the supplied records by decision, definition, constraint, metric, and unresolved issue. Cite the work order or memory item for each material fact.
3. Compare conflicting statements by date, owner, scope, and directness. Report the conflict when the authoritative version is unclear.
4. Separate confirmed context from assumptions and questions. Note the specific source or owner needed to fill a gap.
5. Return a brief context note that the next specialist can use, then state the analytical task it enables.

This procedure does not grant source access. An admitted built-in Researcher may search and fetch public HTTPS pages when web tools are configured and allowed for the run. Email, calendar, and raw repository or artifact text are not available through the live text path. Cite only sources actually supplied or returned by an admitted tool.
