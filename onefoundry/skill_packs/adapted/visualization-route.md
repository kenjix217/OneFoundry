# visualization route

Use when a work order spans several visualization types and needs routing before specialist work. Inputs: decision question, available data, audience, output medium, interaction level, and constraints.

1. Select the primary visualization problem: chart, map, schedule, graph, dashboard, report, or interactive story.
2. Name the focused OneFoundry procedure or implementation owner and the evidence needed.
3. Record dependencies and acceptance gates without combining unrelated specialist claims.

Capability preflight: Check that requested data and any renderer, file, or browser capability are actually admitted for the assigned role. A procedure selection alone grants no tool.

Output: Return a short routing decision and gap list; do not present a routed task as an implemented visual. Save a requested Markdown brief only when `write_text_artifact_v1` is admitted.
