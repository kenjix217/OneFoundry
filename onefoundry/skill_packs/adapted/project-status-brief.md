# project status brief

Use this procedure to summarize the current state of one OneFoundry project for its operator. Base the brief on work-order evidence, approved memory, and, when admitted, `project_brief_v1`, `recent_project_work_v1`, or `run_evidence_v1`.

1. Identify the project, reporting cutoff, and the work covered. Read only records available to this run. A recent-work list is bounded; do not call it a complete project history.
2. Separate completed outcomes from work in progress, blocked work, failed or unknown runs, and proposed next actions. A status alone does not prove the requested result was achieved. Use a saved result or corroborated receipt when making an outcome claim.
3. Lead with the operator actions that have an evidenced owner and reason. If none is established, say that no operator action was identified in the reviewed scope.
4. Give a short status in plain language with work-order or run IDs where available. State the cutoff, any important evidence gaps, and what should be checked next.

Return the brief in the run response. If `write_text_artifact_v1` is admitted and the work order asks for a durable note, save a Markdown artifact and report its verified owner record. This procedure cannot update a project summary field, schedule refreshes, change work-order state, or approve actions.
