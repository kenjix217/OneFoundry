# map visual plan

Use this procedure when a work order asks whether location data should be mapped or how a map should communicate a supplied claim. Inputs are the geographic unit, coordinates or region identifiers, measures and denominators, source dates, intended audience, and any sensitivity constraints.

1. Check whether geography is necessary to the decision. If location is incidental, recommend a table or non-map chart.
2. For a map, specify the spatial join or location assumptions, normalization, projection concerns, legend, missing regions, and the difference between measured and inferred layers.
3. Describe scale-dependent labels or clusters, keyboard and text alternatives, mobile reading order, and stale or offline behavior when applicable.
4. List the exact geocoding, boundary, tile, and visual checks required before publication.

Return a written map concept with a source and uncertainty ledger. Do not claim to geocode, fetch tiles, inspect geography, render a map, or perform browser QA. Markdown saving requires admitted `write_text_artifact_v1` and a request.
