## Authority and scope

The existing Tool Gateway owns catalog, package/connection/skill lifecycle, admission, dispatch, approval bindings, and events. Integration Hub and Tool Foundry are views over it. One SDK supplies portable package definitions and authoring tools. Operator-owned JintellarCore code may be copied and adapted. Existing credentials, skill versions, role grants, project boundaries, Execution Gateway, and event protections remain authoritative.

All six slices are authorized; there is no per-slice implementation approval pause. Tests may create isolated local services and apply migrations to disposable databases. Preserve the installed stack's requested shutdown, its data, credentials, and configuration. Installation, deployment, remote publication, paid provider actions, and unknown external effects are separate from source implementation and disposable acceptance. Preserve unrelated modified documentation. Do not commit or push without an explicit instruction to do so.

## Final audit adjustments

- Consolidate every new API and SDK runtime action behind ToolGateway, retaining focused internal modules.
- Keep draft skills outside accepted immutable versions and automatic selection until exact-hash acceptance.
- Use one project-aware descriptor resolver for role advertisement, grants, dispatch, and operator capability selection; retain built-in IDs.
- Snapshot package, descriptor and connection identities per run. A newer package or endpoint cannot change an existing run's capability.
- Claim intent/approval durably, release DB locks, execute, then settle; ambiguous outcomes cannot replay automatically.
- Run untrusted Python and pinned stdio MCP in an isolated worker. Private callbacks carry gateway-issued invocation identities rather than claimed agent IDs.
- Include SDK tests/build, new Postgres tests, worker isolation proofs, real API/MCP/webhook operations, and desktop/mobile acceptance in the executed gates.
- Assign pinned stdio MCP explicitly to slice 4, and generic approval-bound API/MCP writes explicitly to slice 5. Local webhook acceptance does not establish public ingress.
