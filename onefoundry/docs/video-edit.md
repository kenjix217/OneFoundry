# Local video editing candidate

`edit_video_v1` renders media through a separate worker. `video_edit_status_v1` returns durable status and exact artifact/QC; `cancel_video_edit_v1` cancels queued/running work. The default is disabled. A skill grants no permission. No installed profile, services, credentials or database grants change merely by adding this code.

An operator uploads selected project assets to `POST /api/projects/{project_id}/video-edits/assets` with a supported `Content-Type`, raw media body and plain `X-Media-Provenance` header. An optional `work_order_id` query parameter narrows scope; provenance stays out of URLs/access logs. PNG/JPEG/WebP, MP4/WebM and WAV are supported. Inputs are opaque media, kept out of the document text extractor. File IDs, project/work-order scope, hashes and actor are recorded. `input_file_max_project_count` and `input_file_max_project_bytes` also bound media intake. Raw paths, remote URLs, arbitrary commands and filter graphs are not accepted.

The agent supplies a request UUID, width/height, ordered scene asset IDs with trims, contain/cover fit and focal positions, timed plain captions, and optional narration/music assets with start, source trim, duration and gain. Scene durations must align to configured frames; trims must fit source media. Audio must end inside the cut. Extend the last scene to preserve ending speech. Contain preserves the full source; explicit cover can crop it. Caption space is reserved below the picture. Source clipping cannot be repaired by enlarging an export.

The Tool Gateway pins recipe and input hashes. One request key per work order produces one job across retries/call IDs; changed recipes under that key fail. A separate `python -m runner.video_edit_worker` claims jobs with row locks. The child receives only a bounded stdin manifest and selected bytes. Docker has no network, mounts, credentials, daemon socket or receipt store; its root is read-only, nonroot, capabilities dropped and memory/CPU/PIDs/tmpfs/wall time bounded. Container flags and image digest are inspected before launch. FFmpeg uses fixed argv and file/pipe protocols. The child probes bounds, renders, fully decodes, and compares ending audio against its complete separately normalized PCM mix. The supervisor verifies returned identities and publishes through the existing immutable workspace artifact owner.

Jobs are queued, running, cancel_requested, done, failed, canceled or unknown. Only an explicit operator retry of a known failure within `video_edit_max_attempts` requeues the same job. Unknown/crashed attempts are fenced, never automatically retried. Reconciliation marks overdue running jobs unknown after render wall time plus the existing receipt wait bound. Cancellation/revocation before publication prevents an artifact return. An interruption may leave unrecorded orphan bytes; these are never exposed as a completed artifact.

Operator routes are GET `/{job_id}`, POST `/{job_id}/cancel` and POST `/{job_id}/retry` beneath the video-edits prefix. Existing run workspace artifact download/player routes provide exact-byte playback and range reads. The player's Open video link shows the same bytes in a separate tab for complete frame inspection when the task panel has limited space. Native team artifact reports and QA dependency readers use the saved artifact/run IDs and hash. Technical decode/QC does not set operator playback verification or prove intelligibility, subjective sound quality or caption readability.

Settings use the existing precedence: explicit constructor values, then environment, then safe defaults; no env file is automatically loaded. `docs/video-edit.env.example` lists every new setting. Enabling requires a pinned `sha256:` renderer image and an existing private asset root. Docker binary/socket paths come from typed settings and accept absolute local paths only; no remote Docker endpoint is supported. Existing media limits define output/source dimensions, duration, bytes and frame rate. Portrait is supported when the operator configures an appropriate `MEDIA_MAX_HEIGHT` within its existing ceiling. The first slice exports WebM; no paid provider, generation API, TTS model or browser capture grant is added.

## Review and activation

The review patch targets the complete unreleased 0.10.8 candidate. Do not install it over shared dirty work or the separate activity/rework overlays. Before live use the operator must explicitly approve: migration 0077 and the new narrow app grants, private media volume/configuration, exact renderer image installation, separate trusted worker configuration/start, and editing tool IDs for the chosen profile. The worker needs the existing gateway database/artifact owners; Docker access stays with that separate trusted supervisor and never with the app or child. No Compose profile or persistent worker is activated by this patch.

Build the review image with `docker build -f runner/video_edit.Dockerfile -t YOUR_TEST_TAG .`, inspect its image ID, and set the test-only `ONEFOUNDRY_VIDEO_TEST_IMAGE` and `ONEFOUNDRY_VIDEO_TEST_OUTPUT`. `pytest tests/test_video_edit_postgres.py -m integration` uses a scripted native SDK agent and a real separate Docker render. It does not prove a paid/live model connection. The captured four-second fixture contains synthetic tones; human listening remains pending.
