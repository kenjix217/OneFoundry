# Team workflow acceptance

## Completed child revisions (current source)

Open the task conversation and select its completed specialist. In an open,
unaccepted team, a satisfied artifact or text-report child at `needs_review`
offers **Return for rework**. Enter complete revision instructions (10–1,000,000
characters). This operator action preserves the child, previous results,
artifacts and audit receipts, and queues exactly one new turn. The current
assignment waits for the revised confirmed result before Chief synthesis.
The latest full revision remains required context even after ordinary history
falls outside its window; an insufficient context budget fails before a model call.

Active or uncertain execution, pending approval, nested work or a result already
consumed by dependent work requires resolution or a new bounded Chief plan.
Accepted or closed teams cannot return a child in place. Ordinary Send and
Continue still refuse closed children. The root work-order **Return** control
retains its existing behavior; it does not queue a child revision.

A lost response retains the request identity for exact retry/readback. A definite
409/422 rejection preserves editable feedback and refreshes the saved state;
it queues nothing. The selected specialist survives task refresh/remounts in
project/order-scoped browser state; selections outside the team are discarded.
Repeated successful revisions preserve every historical
result identity. This repair uses existing tables and Gateway events and adds no
migration or installed grant. Full regression and disposable-service browser
evidence are recorded in `PROGRESS.md` and the scoped repair handoff. Installed
activation and a paid-provider replay are outside this isolated qualification.
